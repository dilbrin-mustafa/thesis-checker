# ADR 0003 — A synthetic corpus is used until real theses are available

Date: 2026-09-07 · Status: accepted

## Context

The doc 05 exit criterion for Phase 1 is "20+ corpus documents parse", measured
into `research/results/`. `research/corpus/` is empty and no real theses are
available in this checkout. Options were to (a) stall Phase 1 until a corpus
appears, (b) ship parsers with no measurement, or (c) measure against synthetic
documents and say so loudly.

## Decision

Measure against a generated corpus, and label the numbers as regression anchors
rather than accuracy estimates, in the report itself and in the README.

The corpus is generated by `research/scripts/make_synthetic_corpus.py` from
`backend/tests/factories.py` — the same builders the test suite uses — so fixtures
and measured corpus cannot drift apart. Sidecar `.expected.json` files are written
by hand from the sources, not dumped from parser output, so a parser regression
still shows up as a regression. Two documents deliberately degrade the input
(`manual-docx` strips heading styles, `notoc-pdf` strips the ToC) to exercise the
fallback paths rather than only the happy path.

## Consequences

- The Phase 1 exit criterion is **not met**; the PDF `F1 > 0.75` target is
  **unverified**, not achieved. Both statements appear in
  `research/results/ingestion.md`.
- Re-measuring against real theses requires no code change — drop documents into
  `research/corpus/` and re-run `evaluate-ingestion`.
- Scores of 1.00 must never be quoted as accuracy. Anyone tempted to do so should
  read the caveat at the top of the report first.
